**NASADEM mirror and files.** The mirror is OpenTopography's public bucket,
`https://opentopography.s3.sdsc.edu/raster/NASADEM/NASADEM_be/NASADEM_HGT_n35w112.tif` (HTTP 200, 12,669,031
bytes, no login). Header as read:
- GeoTIFF, int16, 3601 x 3601 pixels, 1 arc-second spacing, EPSG:4326.
- `AREA_OR_POINT=Point`, nodata -32768, units m.
- The upper-left pixel centre lies exactly on 36 N, 112 W, so the last row and column are shared with the
  neighbouring tiles.

The Copernicus tile N35W112 has the same transform origin, with 3600 x 3600 float32 pixels, `AREA_OR_POINT=Point`
and no nodata value.

OpenTopography's own metadata page for the dataset
(https://portal.opentopography.org/datasetMetadata?otCollectionID=OT.032021.4326.2, DOI 10.5069/G93T9FD9) says:
- title: "NASADEM Global Digital Elevation Model"; citation: "NASA JPL (2021). NASADEM Merged DEM Global 1 arc
  second V001. Distributed by OpenTopography." The second citation, "NASA JPL. NASADEM Merged DEM Global 1 arc
  second V001. 2020, distributed by NASA EOSDIS Land Processes DAAC", is the NASADEM_HGT product;
- voids filled with other sources, including ASTER GDEM;
- vertical datum EGM96 geoid (EPSG 5773). Copernicus uses EGM2008: the offset between them is smooth and does not
  change slopes;
- licence: "Not Provided".

What "_be" in the folder name means is UNVERIFIED: the page does not mention it. The files carry the NASADEM_HGT
name. NASADEM is radar-derived, so it is a surface model like Copernicus and not true bare earth.

**Grid alignment.** Pixel offsets of 0 / ±1 pixel against the Copernicus tile give median absolute height
differences of 1.38 m at (0,0) and 1.55 to 1.83 m at the other eight offsets. The two tiles are therefore aligned
pixel for pixel. The median height difference NASADEM minus Copernicus is -0.12 m.

How it is implemented:
1. Drop the shared last row and column, leaving 3600 x 3600 pixels.
2. Resample along x with the same bilinear `scipy.ndimage.zoom` to the width that the Copernicus tile of the same
   name gets after its square-pixel resampling. `copdem_columns` gives Copernicus's native columns: 3600 below 50
   degrees, 2400 between 50 and 60 degrees.
3. Return the Copernicus bounds and pixel size.

`copdem_grid(tile)` reproduced the shape, bounds and pixel size of all 38 cached Copernicus tiles exactly. On
N35W112 the cell latitudes and longitudes were identical in all 2,520 cells.

A side finding that affects both DEMs: scipy's zoom sets the last output column to 0. That column lies in the
partial strip that `cell_grid` never uses, unless the width is a multiple of 64.

**MODIS class decoding.** The layer `MODIS_Combined_L3_IGBP_Land_Cover_Type_Annual` is MCD12Q1 v061 (layer
metadata https://gibs.earthdata.nasa.gov/layer-metadata/v1.0/MODIS_Combined_L3_IGBP_Land_Cover_Type_Annual.json).
WMTS GetCapabilities (https://gibs.earthdata.nasa.gov/wmts/epsg4326/best/1.0.0/WMTSCapabilities.xml) gives:
- times `2001-01-01/2024-01-01/P1Y`. WMS requests for 2000 and 2025 returned fully transparent images;
- colour map https://gibs.earthdata.nasa.gov/colormaps/v1.3/MODIS_IGBP_Land_Cover_Type.xml, which is
  one-to-one: 17 classes plus 255.

The WMS PNG comes back as RGBA. Decoding is by exact RGB match with that colour map, which is copied into
`IGBP_RGB`. All 9 colours of the N35W112 image were found in the map.

Groups:

| Group | IGBP classes |
|---|---|
| bare | 16 |
| ice | 15 |
| water | 17 and 0 (they share one colour), plus transparent no-data |
| built | 13 |
| veg | 1-12 and 14 |
| none | 255 |

Edge cases: 7 Open Shrublands and 10 Grasslands count as vegetation, although WorldCover calls much of that ground
"bare / sparse" or "moss and lichen". MODIS "Barren" is therefore stricter.

On N75W090, MODIS calls 7.1% of the area ice; WorldCover calls 0.03% ice.
