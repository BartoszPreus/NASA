# J26 — Do partner surface observations support the dune flag?

The full run sampled **978 sites** with zero failed tile reads. The temperature contrasts did not separate flagged and unflagged sites across latitude bands. AMSR2 separated them in the sampled data, with **higher** moisture at flagged sites. These observations do not validate the flag as a detector of dry sand. The flag still uses the existing terrain rule.

## Input and method

[GitHub Actions run 43654559980](https://github.com/witczakw/moon-scan-runner/actions/runs/43654559980) ran `python -m pipeline.partner_context --top 200 --flagged 600 --known 400` on the ranking and site catalogue at commit `9f37db3`. After deduplication the sampling strata contain 200 ranked, 521 flagged and 257 additional known sites. The actual site labels include 521 flagged and 298 known sites. A ranked site can also be known. We join by site ID to the published coordinates, flags and terrain rank.

We compare flagged with unflagged sites and, separately, known analogs with the other sites. Each comparison uses signed latitude bands of 10°, with hemispheres kept separate. For each band, the [result JSON](../../data/validation/partner_checks.json) gives the number of sites and tiles with data, each group's median and interquartile range, and the rank-biserial effect and its 90% interval when estimable. A positive effect means the first group tends to have higher values. We require at least five measured sites and three distinct tiles in each group. The interval uses 2,000 bootstrap draws of whole one-degree tiles, shared across groups. The pooled result averages within-band effects weighted by the number of cross-group pairs. A pooled interval crossing zero is reported as no separation supported by this comparison.

## Results

| Measurement | Flagged vs unflagged | Known vs other |
|---|---|---|
| JAXA SGLI day minus night | **Does not separate across bands.** Effect −0.093, 90% interval [−0.194, +0.037], 7 evaluable bands. | **Separates in this sample.** Known sites tend higher, +0.319 [+0.179, +0.440], 5 bands. |
| NASA MODIS day minus night | **Does not separate across bands.** Effect +0.055 [−0.065, +0.178], 7 bands. | **Does not separate across bands.** +0.010 [−0.146, +0.157], 5 bands. |
| JAXA AMSR2 soil moisture | **Separates in this sample.** Flagged sites tend wetter, +0.396 [+0.259, +0.503], 5 bands. | **Does not separate across bands.** −0.015 [−0.191, +0.273], 5 bands. |

For example, at 30–40° N the flagged group had median AMSR2 moisture of 5.97% across 65 sites, compared with 4.39% across 24 unflagged sites. The band effect was +0.710 with interval [+0.516, +0.848]. All five evaluable AMSR2 bands had positive flag effects and four intervals excluded zero. MODIS day–night values separated the flag groups in two bands but the pooled interval crossed zero. The known-site temperature effect seen by SGLI did not repeat in the pooled MODIS result. [Band-by-band figure](../figures/partner_checks.png)

SGLI, MODIS and AMSR2 had 978, 976 and 899 usable observations respectively. Clear-sky day–night contrasts use only months with both a day and a night value. At high latitude this often omits winter and midsummer. SGLI samples 2021, while MODIS and AMSR2 are monthly normals from 2012–2021. Different overpass times and footprints limit cross-sensor comparisons.

The percentages are satellite retrievals around each site. Coarse pixels can cover several ranked patches. Latitude bands limit one geographic difference. Elevation, regional climate, surface type and retrieval coverage can still differ within a band. The sample was selected by rank and site labels, and the terrain flag supplies the groups rather than independent dune ground truth. The bootstrap intervals are exploratory and have no adjustment for multiple comparisons.

## Reproduction and credits

With the existing Python environment, replay the exact minimal sample saved in `observations` inside the result JSON:

```sh
python validation/partner_checks.py --from-results data/validation/partner_checks.json
```

For a new cloud sample, `python -m pipeline.cloud run-partner-context` requires an authenticated GitHub CLI and write access to the team runner. Downloaded input is staged under `data/raw/j26/<run_id>/`. Run `python validation/partner_checks.py --context data/raw/j26/<run_id>/partner_context.csv --run-id <run_id>` from the repository root. The JSON records the source CSV hash. The expanded cloud sample does not replace the published J24 site context table.
