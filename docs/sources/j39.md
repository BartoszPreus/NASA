# J39: App data export of every backend output (issue #25)

Written with SI assistance (Claude Code), Sun 15 Nov 2026.

## What it is

`app/build_data.py` and `app/validation_data.py` now export every backend output that `docs/FRONTEND-SPEC.md`
(J38, issue #24) lists as missing from `app/data/` (section 6.1, gaps G-01 to G-14, and section 6.2). The contract is
`app/data/SCHEMA.md`; `tests/test_app_export.py` checks that each of its keys exists in the committed export and
`tests/test_pipeline_integration.py` builds the export from the sample and checks the same keys.

## Inputs (all in git)

No external page, dataset or service was opened for this job. The export reads only committed files; the full list
of the files read by a build is `app/data/meta.json · inputs`. The data sources behind those files are cited in
`data/sources.csv` and the notes of the jobs that produced them (`docs/sources/j*.md`).

Reference only, never read by the build: the J7 prototype data layer kept outside git
(`scratch/app_local_backup_0119/`: `build_data.py`, `data/SCHEMA.md`, `criteria.json`, `CRITERIA-NOTES.md`). Its
criteria registry was ported into `app/criteria.json` and re-checked; the changes are listed in
`app/CRITERIA-NOTES.md`.

## Libraries

- Pillow (https://python-pillow.org/, MIT-CMU licence, already in `requirements.txt`): figure re-encoding and
  palette PNGs.
- NumPy (https://numpy.org/, BSD-3-Clause, already in `requirements.txt`): pixel comparison of repacked PNGs.

## Decisions

- **Additive.** No key that `app/app.js` or `app/views.js` reads was renamed or removed; the files the page reads as
  lists stay lists. Files with a list at the top (`sites.json`, `method.json`, `sources.json`) could not take top-level
  keys, so their metadata went into new files (`site_info.json`, `method_sections.json`).
- **Size.** A plain copy of every image and figure made `app/data/` 25.7 MB, over the 25 MB limit. Two steps bring
  it to about 23.7 MB without changing what an image shows: lunar PNGs of at most 256 colours are stored as indexed
  PNG with the same pixels (checked pixel by pixel in the build), and the five figures over 600 kB are stored as
  JPEG quality 90 at their original pixel size (`top30_sheet_1..3`, `radar_earth_vs_moon`, `morasko_1m_vs_30m`).
  Two bulky per-row blocks that no screen shows are left out of the exported validation files and named in
  `_omitted_by_app_export` (`effectiveness.json · ablation.per_tile`, `partner_checks.json · observations`).
- **Joins by site id check the position.** A side table row is attached to a site only if the id and the position
  agree (0.02 deg latitude, 0.05 deg longitude). For `rank_uncertainty.csv`, `radarsat1_index.csv` and
  `sites_top100.csv` a disagreement stops the build; `novelty_check.csv` also holds rows of older rankings, so its
  rows are attached only where the position agrees (32 of 44 rows today; the other 12 have no site of the current
  run at their position).
- **Strict-mask ranking (#19).** `ranking_bare_strict.csv` comes from a separate sites run; its site ids are
  numbered within that run, so the export does not join it to the default sites by id.
- **Distance radius.** `distance_km` now uses R = 6371.0088 km, the value of `pipeline/sites.py EARTH_R_KM` that its
  docstring claimed to use (it used 6371.0). Six `nearest_lunar_known_km` values change by 0.1 km.
